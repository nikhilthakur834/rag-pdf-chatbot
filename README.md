# RAG PDF Chatbot

A Retrieval-Augmented Generation (RAG) application that answers questions from PDF documents.
Every answer is grounded in the uploaded documents and cites the source file and page number.

**Live demo:** https://rag-pdf-chatbot-ef7szn2ukrrhyrrneg5rbq.streamlit.app/

## Features
- Upload one or more PDF files and ask questions in natural language
- Semantic search over document chunks using embeddings and a FAISS vector index
- Answers generated by Google Gemini using only the retrieved context
- Source citations (file name and page numbers) with every answer
- Hallucination guardrail: replies "The document does not contain this information." when the answer is not found
- Retry with exponential backoff and a fallback model for temporary API errors

## How It Works
1. **Load:** Extract text from each PDF page (pypdf).
2. **Chunk:** Split text into overlapping chunks of 500 characters (50-character overlap).
3. **Embed:** Convert chunks into vectors using the `all-MiniLM-L6-v2` sentence-transformer model.
4. **Index:** Store the normalized vectors in a FAISS index for cosine-similarity search.
5. **Retrieve:** Find the top matching chunks for the user's question.
6. **Generate:** Send the question and retrieved chunks to Gemini with instructions to answer only from the context.

## Tech Stack
Python, Streamlit, pypdf, sentence-transformers, FAISS, Google Gemini API

## Run Locally
```bash
pip install -r requirements.txt
```
Set your API key, then start the app:
```bash
# Windows PowerShell
$env:GEMINI_API_KEY="your_key_here"
streamlit run app.py
```

## Project Structure
- `app.py`: Streamlit user interface
- `rag_engine.py`: embeddings, vector search and answer generation
- `pdf_loader.py`: PDF reading and chunking

## Limitations
- Scanned (image-only) PDFs are not supported, as there is no OCR.
- Text inside images and diagrams is not extracted.
- Retrieval is based on meaning, so questions like "what is on page 5?" may not work.
